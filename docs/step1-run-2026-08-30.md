# Step 1, RUN — the receiver and the decoy bidder driven over a synthetic corpus

*2026-08-30. `tools/adint-step1-run --seed 20260830`, on mesh-home. Artifacts:
`receiver/testdata/step1-2026-08-30/`.*

## What changed, and why it is not a document about the receiver

`receiver/` has carried unit gates since 2026-08-15 and they passed the whole time. What
it had never had is a **run**: the shipped binary started as a process, spoken to over a
socket, driven by a corpus, and leaving artifacts that were then read back and asserted.
The distinction earned itself within one drive — the first run found a defect eight unit
tests had not, and it is a defect only a run could find (below).

Three of this harness's checks cannot be made in the package's own tests, and they are the
reason it exists rather than a preference about style:

- **The leak sweep reads the real process's stdout+stderr and the real files under the
  data dir.** A unit test calls the handler in-process with a captured logger. It cannot
  see what the shipped `main()` wires up — and `main()` is exactly where a logger, an
  access log or a framework default would leak. `CLAUDE.md` rule 2 says the privacy
  invariant is a **construction, not a discipline**; a construction has to be checked on
  the constructed thing.
- **The on-disk JSONL is parsed back and joined to the corpus by request id**, so "only
  the target device's rows reach disk" is asserted over the artifact a reader would audit,
  not over a mock's call log.
- **Latency exists at all.** There is no RTT without a socket, and §1e's bid budget is
  `tmax` minus RTT.

## The corpus

57 requests, generated deterministically from seed `20260830`, five classes — each present
to make one branch reachable:

| class | n | what it must produce |
|---|---|---|
| `matched` | 20 | `device.ifa` == the target → bid, **and** the only class that may reach disk |
| `foreign-pass` | 20 | a different ifa, bundle in the allowlist → **bid on, never recorded** |
| `foreign-deny` | 10 | a different ifa, bundle not allowed → 204 |
| `no-ifa` | 5 | no `device.ifa` at all → must not match on an empty-string comparison |
| `panic` | 2 | `__panic` **plus** a foreign ifa, so `recover()` runs with a foreign identifier live in scope — the §1b leak condition |

Half the imps carry a floor and half do not; the no-floor half is the one that can win
outright in a first-price auction, which is what the ledger and the cap exist for (§1a).
Every request carries `tmax`, `at` and `bidfloorcur`, and every `device.geo` carries real
`lat`/`lon` — the coordinates are in the corpus **on purpose**, so that their absence from
the artifacts is a measurement rather than an assumption.

The target ifa is the fixed fake UUID `00000000-0000-4000-8000-000000000001`. Nothing in
this run is about a person, which is what lets the output be committed at all.

## What the run found that the unit tests did not

### 1. The one-shot win alert was spent on a zero-price win

`Ledger.recordWin` alerted on the **first win of any price**, while its own comment — and
§1a — say *the first non-zero win*. Driven over the corpus this fired immediately, because
the realistic first win notice is the one whose `${AUCTION_PRICE}` the exchange failed to
substitute: `parsePrice` correctly reads the literal as 0, and the alert then wrote

    FIRST NON-ZERO WIN: price=0.0000 spend=0.0000 cap=0.5000

a sentence false on its face — and **latched**, so the first actual spend would have
arrived in silence. The unit test passed because it drove a non-zero win first, which is
the one ordering the failure cannot appear in.

Fixed in two halves, because suppressing the false alert must not become swallowing the
event:

- the latch now requires `price > 0`;
- a zero-price win raises its **own** loud marker (`WIN-ZERO-PRICE.txt`, a log line) and is
  counted apart in `zero_price_wins=`, which now rides in `win-counter.txt` itself. Winning
  an impression whose price we cannot read is the state in which a spend counter silently
  understates, and **spend is a lower bound** whenever that counter is non-zero. Netting it
  into spend would erase exactly the evidence that spend is untrustworthy.

`TestAlertNotSpentOnZeroPriceWin` now carries it in the package too, seen red under the
one-word reversion.

### 2. Past the cap the receiver stops bidding and keeps recording — nothing said so

The post-cap probe is written to disk twice, and the second response is 204: persistence
happens **before** the cap check. That is the behaviour worth having — the point of the
project is to observe his own device, and observation should not stop because the budget
did — but no line of code or test said it, and both plausible ways of writing the
completeness gate (set equality, or `== len(matched)`) would have been wrong about it in
opposite directions. It is now `records-continue-past-the-cap`, with a mutant.

### 3. A gate of mine passed for the wrong reason

`spend-cap-halts-bidding` originally probed with `corpus[0]`. The corpus is shuffled, and
when position 0 was a `foreign-deny` request it answered 204 because it had been
**filtered**, not because the cap had halted anything — the mutant that deletes the cap
check stayed green. The probe is now explicitly a matched request. A gate whose expected
value is also produced by an unrelated branch is not a gate, and only the mutation drive
exposed it.

### 4. Two mutants did not compile, and "did not build" was reading as "stayed green"

The obvious leak mutation — logging `req.Device.IFA` from inside the deferred `recover()` —
does not compile, because `req` is declared after the `defer`. `if false {` for the sink
leaves `matched` declared-and-unused, which Go also refuses. The harness reported both as
*STAYED GREEN — the gate does not test this*, which is the opposite of the truth. A mutant
that never built is an **inconclusive arm**; it now says so and still fails the selftest,
because an experiment that did not run is not a pass.

## Timing, and what this run does *not* license

Observed service time on loopback: **p50 0.278 ms, p95 0.422 ms, max 0.632 ms** over 55
non-panic requests, against declared `tmax` values of 80/100/120/150 ms.

That number is nearly meaningless for §1e and must not be quoted as headroom. §1e's budget
is *`tmax` minus RTT*, and **RTT here is zero by construction** — the corpus is on the same
host. What the run establishes is only that our own decision cost is sub-millisecond, so on
a real seat the entire budget is spent by the network and by the exchange's point of
presence, not by this code. It also records plainly that **the receiver reads neither
`tmax` nor `at` today** (`tmax_read_by_receiver: false`, `at_read_by_receiver: false`) —
the corpus carries them so that this is a measured absence rather than an unasked question.
Reading them is Step 1e work and is not done here.

## Egress, recorded in the same run as the claim

The board task asks that every cell record which egress it left by, because this repo has
already published a figure that was privoxy's far end rather than the node's route. So the
run measures **both legs** and neither is inferred:

| leg | ip | country | asn |
|---|---|---|---|
| as-invoked (proxy env honoured) | 38.49.216.141 | US | AS197537 Wisdom Cloud |
| proxy env stripped | 38.49.216.141 | US | AS197537 Wisdom Cloud |

`proxy_env` in this pane was `HTTP_PROXY=HTTPS_PROXY=ALL_PROXY=http://127.0.0.1:8118`, so
the first leg **was** proxied — the trap was live, and the two legs agree only because this
node consumes phaedra as its tailscale exit node while privoxy's socks tunnel lands on
phaedra too. The agreement is a measurement, not a property; on a day when the direct route
is not the exit node's, these will differ. `legs_agree: true` is recorded per run.

Receiver traffic left by **neither**: it is `loopback-only`, 127.0.0.1 on an ephemeral
port, and the corpus never left this host. The harness itself did make two external
`ifconfig.co` requests for egress provenance; those requests were separate from the
receiver and its corpus. The new `--offline-egress` option skips those requests and records
egress as `unknown`; `--test` now always uses that mode.
